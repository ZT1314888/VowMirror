## 接口与数据边界（目录与 Phase 3 生成 API 已实现）

入口 `http://localhost:3000`；Nginx `/api/` 转发后端 `:8000`。健康 `GET /api/health` 不调用模型，不返回配置或凭据；公开目录 `GET /api/catalog/outfits` 仅返回版本、套装 ID／名称及场馆 ID／名称，生成 `POST /api/tryon/couple` 需要 Token。未列出的路由一律 404。
JSON 请求字段：`couple_image`（Base64/Data URL）、`outfit_id`（W001–W030）、互斥的 `scene`（原背景／上传场地／后续真实场馆）；生成保留原左右站位，婚纱穿着者由模型依据合照判断。原背景不得带场地图，不设左右肖像字段。
客户端不能指定服装路径／URL、Key、Base URL 或任意模型名。服务端从唯一清单读取套装。响应一张已验证图片、真实 MIME、实际模型和请求标识；统一错误封装，不含原始上游正文或敏感配置。
核心接口改为有序角色参考图，每图含角色、字节和真实 MIME，另含提示词与输出规格。四张必填参考是合照、婚纱、男装、男鞋特写；加可选场地图最多五张。不支持完整参考能力必须报错，不得丢图继续。生成器、安全服务、素材读取器构造注入。

### Phase 3 代理超限错误修正（2026-11-14）

独立审查发现实际 Nginx 入口的超限请求返回默认 HTML 413 且没有请求 ID，先前直连后端的 413 测试未覆盖该路径。修改前将八份既有草稿逐字节备份至 Git 与 Docker 均忽略的
`.local/backups/p3-body-limit-fix-20261114`，清单记录 SHA-256 与整合去向，各文件修订仍整合在原路径。

实测仅取消代理预检会把流式上传中后端的提前拒绝转换为代理 502，因此保留原有 24 MiB 传输边界，并为代理拒绝补齐标准 JSON `41301 / REQUEST_TOO_LARGE`、服务器生成且头／正文一致的请求 ID、
`no-store` 及原有安全响应头。安全头抽取到共用配置，避免 Nginx 子 location 的头继承规则导致遗漏；超限连接关闭，不复用未完成上传。

同时定位到 GoFrame 默认的 8 MiB 请求体包装：9 MiB 空白前缀加有效 JSON 的请求本应进入模型配置校验，却提前返回 413。生产服务器显式关闭该隐式限制，后端保留现有 24 MiB 业务读取限制；固定长度和分块的 9
MiB 生产服务回归均通过，不调用模型。

本轮 Go 全量测试、gofmt、vet、构建和 78 项 Node 测试已通过，web/backend 已构建并重新创建。真实 Playwright MCP 已确认固定长度超限返回标准 JSON 413 与一致的请求 ID。最终
`docker compose run --rm -T tools-browser` 退出 0：固定长度、显式 HTTP/1.1 分块及未鉴权超限均返回标准 JSON 413；请求 ID 由服务器生成、头／正文一致，不回显客户端标记；
`no-store`、CSP、Referrer-Policy 与 nosniff 均存在。四种视口、鉴权、非法输入、私有文件隔离、键盘、错误与重试的完整 Chromium 烟测通过，页面异常为零。
