# 合照人脸数校验

选图时只做本地格式、大小和预览检查。点击生成，通过生成码、并发和额度检查后，
服务端复用合照校验已解码的像素，只对 `couple_image` 计数。至少两张脸才继续读取素材和调用模型。
这项检查不判断人物身份或伴侣关系，也不会在多人照中指定两位主角。

## 服务行为

- 使用固定版本的 [Pigo 模型和公开测试照片](../../backend/internal/facedetect/README.md)。
  检测副本校正 JPEG EXIF 方向，按比例限制最长边为 2048 像素；发给生成模型的字节保持原样。
- 场地图、服装图、生成结果不参与计数。检测失败或请求取消时，释放并发槽，不计入尝试或成功次数。
- 检测在 HTTP 200 事件流打开后执行。失败只发一个 SSE `error` 终态，错误状态放在 `data.http_status`。
- 不足两张脸：`42210 COUPLE_IMAGE_NOT_COUPLE`，状态 422，提示换一张两人面部清楚的照片。
  检测不可用：`50307 FACE_DETECTION_UNAVAILABLE`，状态 503，提示稍后重试。
- 照片、检测框和人脸特征不落盘、不写日志。侧脸、遮挡和逆光可能导致漏检。

## 验收与集成

真实检测器覆盖零脸、单脸、双脸、三脸和旋转 JPEG；服务测试检查拒绝与取消时的额度和并发。
HTTP 验收核对流的唯一终态，用双脸加无人场地图验证输入边界。
浏览器验证选图时没有上传、提交后显示少脸提示、换图后可重试。验收使用空模型凭据和受控上游。

工作分支为 `feat/couple-face-gate`，基线为 `d588f7d6`，与 UI 和姿势工作树隔离。
后续合并时须联合回归生成顺序、姿势处理和错误码；本功能不占用姿势分支的 `42209` 或 `50306`。
