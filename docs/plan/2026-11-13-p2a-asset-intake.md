# P2-A 素材接收记录

日期：2026-11-13

本轮接收两组由用户提供的本地素材：30 套服装，每套包含婚纱、男装带鞋和男鞋特写三张 JPG；30 张白底双人姿势图，编号为 P001–P030。原始文件未写入文档、日志或 Git，仓库内只保留本地运行目录和可审计的相对路径清单。

## 已完成

- `assets/wedding/manifest.json` 固定了 W001–W030、三类服装角色和 P001–P030 姿势的唯一相对路径。
- 服装名称按随素材提供的编号对照表录入。
- 服装和姿势图片目录被根 `.gitignore` 忽略；清单可以进入审查和 Docker 构建上下文。
- `node scripts/verify-wedding-assets.mjs assets/wedding/manifest.json --check-files` 检查 90 张 JPG 与 30 张 PNG 的存在性、非空状态和文件签名。
- 后端 `GET /api/catalog/outfits` 从固定 `/assets/wedding/manifest.json` 读取清单；目录接口要求访问 Token，健康检查不读取清单、不调用模型。

## 工程修复与复验（2026-11-13）

本轮仅收敛工程问题：以 Node 规则为基准，Go 与 Node 共同使用 57 个清单契约用例。两个数组允许重排，但必须完整覆盖 30 套服装与 30 个姿势；两端拒绝未知字段、空白名称、跨套／重复／逃逸路径、缺失姿势及错误状态。重复 JSON 键采用末值语义，空白判定与 ECMAScript 一致。

目录加载函数通过内部构造函数注入，生产仍固定读取打包清单，不允许客户端指定路径。接口测试验证无 Token／错误 Token 401、有效 Token 200、清单缺失／损坏／不合法 500，以及健康和鉴权失败不读取清单、错误响应不泄漏原始内容或路径。

浏览器烟测删除目录接口的过期 404 断言，改为验证 401／401／200、清单元数据、`no-store` 和素材文件 404。访问 Token 仅在运行时传给工具容器，不进入页面或存储；敏感请求异常脱敏后重新抛出，不吞错。
