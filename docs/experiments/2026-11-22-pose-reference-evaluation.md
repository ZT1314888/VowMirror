# 姿势参考上游验证与对照试验

历史实验归档，来源为 `test/pose-reference-upstream-validation` 与 `test/p007-strong-pose-instructions` 工作树。
以下状态、结果与计划保留归档时的原文含义；实验代码未合入产品，本文不代表新的实施或付费调用授权。
代码路径均指实验工作树中的文件；图片和完整原始证据继续保存在 Git 忽略目录。

基线为 Phase 8 的 `aef57f4`。实验仅在后端接受清单中的 `pose_id`，前端没有新增控件。
参考图依次为合照、婚纱、男装、鞋履、可选场地、可选姿势。姿势参考只指导肢体位置、距离和接触；
人物身份和左右位置仍以合照为准。模型、服务商及出口均沿用本地配置。

## 对照方法

同一组合照、套装、上传场地和基础提示词。离线选用 P001（牵手）、P007（抱举）和 P021（双人跃步），
每种姿势三组，每组各请求一次无姿势和带姿势。场地条件下两组分别发五图和六图。
首条请求先验证六图；若上游明确拒收，才改为原背景下的四图／五图配对，不重试或更换模型。

实验脚本（实验工作树 `scripts/pose-evaluation.mjs`） 通过现有生成 API 调用，使用独立 Compose 项目、新用量卷和临时令牌。
每个令牌的每日尝试上限设为 18，脚本另设全场 18 次总上限。服务器未保存照片或生成结果。
结果图只保存在本机 Git 忽略目录，不附在报告中。费用及供应商是否继续处理超时请求不能由本地响应判断。
从试验工作树运行 `node scripts/pose-evaluation.mjs --verify-inputs [data-root]` 只校验输入。
获得真实调用授权后，`--run [data-root]` 执行试验；当前工作树须备好所选服装与姿势文件供 Compose 只读挂载。
若使用独立工作树，可将私有接收清单、运行时配置和结果目录留在原数据目录，以 `data-root` 指定该目录。

逐图目检以线稿的主要动作、肢体角度、人物间距和接触点为判断依据。
姿势记为匹配、部分匹配或不匹配；同时比较可见肢体完整性、遮挡和接触是否自然、人物外观和左右位置、
服装和鞋履、全身构图及场地。只将两次请求都返回有效成片的组计入配对比较；超时不补跑、不记为姿势失败。

## 验证

- Docker 内 Go 定向与全量测试、格式、`vet`、构建及 Node 检查通过；夹具覆盖旧四／五图与新五／六图顺序，
  以及非法编号、缺失素材、无效字段及错误的参考图顺序。
  最终增补姿势文件损坏、格式不符、大小超限、目录和符号链接逃逸的定向测试后，再次通过全量 Go 检查。
- Docker 真实 Chromium 检查通过，覆盖授权、生成、取消、场地图上传及刷新后的状态清理。
  浏览器 MCP 在试验实例确认健康和目录均返回 200，前端未显示姿势控件，目录和静态路径未公开姿势图。
- 私有输入通过完整解码和接收摘要核验，选定素材满足单图和总量边界。
- 最终核对 18 条请求记录、17 张输出及 8 组完整配对；报告耗时逐项匹配原始记录。
  修改文件的差异、凭据模式扫描及本地 Markdown 格式／链接检查通过，暂存区为空。

## 结果

**当前上游接受六图，但加入姿势图未能稳定复现目标动作。** 实际发送 18 次，无重试、无模型切换。
六图组 9/9 获上游 HTTP 200 并交付有效 `1536 × 1024` PNG；五图对照组 8/9 成功。
首条六图耗时 52.155 秒，因此全程保持上传场地，没有启用原背景备用设计。
一次五图对照在 85.008 秒时以 `504 / GENERATION_TIMEOUT` 结束，当时未收到上游响应头。

表中每项为“端到端秒数／收到上游响应头的秒数”。除单独标出的超时外，上游及业务状态均为 200。
成功响应记录的请求模型为 `gpt-image-2.5-flare`；上游均未提供可用的型号快照或请求标识。

逐图目检中，人物外观与左右位置整体接近合照；成片均保留了场地的白色布幔、庭院和座椅等主要元素，
细节与摆位略有变化。站姿图的服装样式和全身取景大致保留，未见明显多肢或画框裁脚；
裙摆常遮住一人的腿脚，部分手和男鞋被身体或衣物遮住，因此不能判为完整展示全部四肢和鞋履。
唯一的抱举图复现一人站立托抱、另一人双腿离地的主要动作，托举接触合理；两人都完整入框，
但婚纱在腿部呈包腿状，并生成了浅色高跟鞋，不能据此确认精确的服装保真。没有明显观察到线稿主体或背景被复制进成片。

本轮能确认六图出图链路，不能确认上游稳定使用了第六张图，也不能区分参考排序、原合照姿势和提示词约束的影响。
单一合照、套装、场地与小样本不足以验证通用效果。试验容器、网络及新用量卷均已清理。
