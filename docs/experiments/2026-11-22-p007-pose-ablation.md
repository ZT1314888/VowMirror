## 不变量与实现

直接省略旧请求的 `pose_id` 会恢复合照原左右位置约束；直接照搬上轮完整提示词又会引用缺失的第六张图。
因此本轮属于实验配置与共享提示词构造的结构性调整，保持普通请求原行为。

- `backend/internal/logic/tryon/couple.go` 在唯一提示词构造中增加显式实验 profile。
  两组共享身份、服装、场地、托背托膝下及头右腿左文字，并允许重新摆姿。
  姿势线稿描述改为“如提供额外线稿”，不要求不存在的 `reference 6`。
- `backend/internal/cmd/couple.go` 从运行时 `POSE_EVALUATION_MODE=p007-ablation` 注入实验 profile。
  未知配置明确失败；实验只接受 W001、上传场地及可选 P007。
  浏览器不能指定提示词或实验模式，普通配置不改变无姿势行为。
- 实验入口（实验工作树 `scripts/pose-evaluation.mjs`） 增加 `--verify-ablation` 和 `--ablate-p007 [data-root]`。
  两次使用同一合照、W001、上传场地、模型、参数及 85 秒后端期限，前五图顺序和字节相同。
  无图组只省略末尾 P007；两组最终提示词字节及摘要必须完全一致。
- 随机确定本组先后顺序并保存日程。脚本总请求上限为 2，两枚临时令牌各限一次。
  不自动重试、删除场地或更换模型；错误和超时先记录，未返回两张有效成片不算有效配对。
  新 Compose 项目与专属用量卷用于真实请求，结果仅保存到 Git 忽略的本机目录。
